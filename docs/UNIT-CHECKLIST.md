# Чек-лист юнита

Как наполняется один юнит (задача 9: один юнит — один чат). Формат полей — `docs/DATA.md`, план курса — `docs/PLAN.md` (сгенерирован `tools/plan.mjs`), проверки — `tools/validate.mjs` и `tools/audit.mjs`, выгрузка для рецензента — `tools/review.mjs`. Нормы ниже совпадают с `NORM` в `audit.mjs`: поменял здесь — поменяй и там.

## 0. Перед началом
- [ ] Прочитать паспорт, `COURSE.md`, этот чек-лист; восстановить нужные файлы (`js/markup.js`, `js/data.js`, `js/render.js`, `js/words.js`, `tools/*`, `data/*`).
- [ ] `node tools/audit.mjs N` — для юнита без файла печатает план: кандзи, главные слова, спираль.
- [ ] Открыть юнит в `docs/PLAN.md`: запас слов, база N5–N4, «что проверить» по этому юниту.
- [ ] Если юнит отступает от плана (другой кандзи, слово переехало) — поправить `tools/plan-config.json` и перезапустить `node tools/plan.mjs`, а не править `docs/plan.json` руками.

## 1. Слова и кандзи
- [ ] **25–35 слов и коллокаций** (`words` + коллокации в `phrases`): главные слова плана — основа; заменять можно на более живое по теме, если оно частотное.
- [ ] **4–8 живых реплик** (`pos: "phrase"`, `reg: "colloq"`) — там, где тема даёт повод реагировать.
- [ ] Коллокации, а не голые слова: не 熱, а 熱が出る / 熱を測る; самые важные — отдельными записями `pos: "col"`.
- [ ] Каждое слово — в `dict.json` с `u: N`, `r`, `m[]`, `pos`; `reg`, если регистр не нейтральный; `note` — где русская мысль ведёт к кальке.
- [ ] **Слово внутри конструкции не считается предложением**: `{出しておく|teoku}` не даёт строку корпуса слову 出す. Каждому слову и фразе юнита — **2+ предложения текстов или банков, где оно стоит отдельной разметкой** `[слово]`, хотя бы одно — в словарной форме (для «Слова в контексте»). Реплики-реакции тоже должны звучать в текстах, а не только в играх.
- [ ] `pos` для «Слова в контексте» — один из `n`, `n,vs`, `adj-i`, `adj-na`, `adv`, глагол; у `n,adj-na` задания не будет — выбрать основное.
- [ ] **10–16 кандзи** (`kanji`), каждый — хотя бы в одном слове юнита (кандзи через слова). У каждого в `kanji.json`: значение и **все частые он/кун** — `audit` покажет недостающие по словам N5–N3.
- [ ] Для кандзи-карточки k-read у знака должно быть 2+ слова в словаре (своё + из прошлых юнитов или коллокация).
- [ ] Глаголы внутри конструкций (`{消しておく|teoku}`) — в словаре, **обе половины пары 自動詞・他動詞** (消える и 消す, 出る и 出す): по ним `innerWord` выбирает слово и фуригану.
- [ ] После правок словаря и кандзи — `python3 tools/fmt.py`.

## 2. Конструкции и банки
- [ ] **4–6 конструкций**; у каждой в `grammar.json`: `pat`, `m`, `form`, `nuance`, `cmp` («не путать»), `detect`, `ex`, **1–3 пары** «Почувствуй разницу».
- [ ] **Банк 20–30 предложений** на конструкцию: короткие (3–8 кусочков для «Собери фразу»), разные ситуации и слова, не один шаблон с подменой.
- [ ] У каждого предложения: `ru` (живой смысл, по нему выбирают), `opts` — **3 неверных варианта** из конструкций юнита и «не путать», `why`.
- [ ] Варианты **в той же форме**: вежливость — всегда (иначе ответ видно по форме), время — где вариант остаётся грамматичным.
- [ ] **Ровно один верный** вариант по смыслу `ru`: прочитать каждый вариант в предложении и спросить себя «а это тоже можно сказать?». Частые ловушки (рецензия юнита 2): 自動詞＋ている рядом с 〜てある (並んでいる ≈ 並べてある); 〜てある с агентом (連絡してあります ≈ 連絡しておきました); каузатив 〜させて(ないで)ほしい читается и как «заставь их»; 〜ておく рядом с 〜っぱなし, если в `ru` нет ни умысла, ни небрежности. Русская скобка «(специально)» не спасает — смысл должен быть виден и в японском.

## 3. Тексты
- [ ] **2 текста разных жанров** (диалог / чат / блог / интервью / новость / эссе / отзыв / письмо / рассказ / памятка), третий — по необходимости.
- [ ] В текстах — все слова юнита и **спираль**: 70 %+ слов из списка «Спираль» плана возвращаются в тексты или банки.
- [ ] Перевод `tr` — по строке на абзац (в чате — на реплику), живой русский, не подстрочник.
- [ ] Чат: реплика — абзац с `имя：`; первый говорящий — справа.

## 4. Заметки и кальки
- [ ] **5–12 заметок** `notes`: «по-русски думаем так → японец скажет так».
- [ ] **10–15 калек** `calques`: две кальки разметкой, их слова — в словаре с заметкой, почему не годятся (без `u`). Кальки — правдоподобные ошибки русскоговорящего; грамматически верная фраза с другим смыслом — только с пояснением в `note`.

## 5. Данные игр
- [ ] `iikae` — **3–4 на конструкцию**: `ok` — пересказ без конструкции, `bad` — те же слова с соседней конструкцией.
- [ ] `collocations` — **12–16**; `bad` — кальки, омофоны, «другой смысл»; глаголы с кандзи — в словаре. Проверить, что `bad` не живёт в разговоре (洗濯機をかける, ドアが閉じる — живут).
- [ ] `register` — **8–10**; адресат однозначно задаёт регистр.
- [ ] `replies` — **10–14**; реакции из фраз юнита, каждая реплика юнита — хотя бы в одном задании.
- [ ] `chats` — **8–10**; `use` — конструкции юнита, в `model` каждая стоит `{…|gid}`.
- [ ] «Слово в контексте» и «Чтения» берут данные сами: чем больше строк со словом **в словарной форме** (глагол, い-прил.) или целиком (существительное, основа перед する), тем больше заданий.
- [ ] Фразы игр — **свои**, а не копии предложений банка: одно и то же предложение везде учит запоминать ответ.

## 6. Письмо
- [ ] **2–3 ситуации** с разным адресатом и регистром (друг / коллега / дневник): `situation` и `plan` по-русски, `use`, `models`.
- [ ] `incoming` на японском — без конструкций юнита и ключевых слов ответа; у дневника — `heading`.

## 7. Язык (каждую строку)
- [ ] Живой современный японский: так говорят и пишут носители в речи и переписке. Книжное — только с `reg: written|formal`.
- [ ] Разговорные формы (〜ちゃう, 〜てる, んだよね, って) — в чатах и репликах; вежливые ситуации — です／ます.
- [ ] Никаких калек с русского; естественный порядок слов; частицы с пояснением там, где их легко понять не так (`(の:…)` в конце фразы).
- [ ] Числа, время, имена — правдоподобные; имена собеседников — японские и разные в разных юнитах.

## 8. Проверка
- [ ] `node tools/validate.mjs` — **0 ошибок**.
- [ ] `node tools/audit.mjs N` — **0 ✗**; каждую «·» прочитать и решить: исправить или оставить осознанно.
- [ ] **Свежий взгляд** — отдельный агент-рецензент, не видевший работы. Получает выгрузку `node tools/review.mjs N > review.md` (весь юнит с чтениями, в т. ч. внутри 【конструкций】) и проверяет: естественность (сказал бы так носитель?), чтения и фуригану, однозначность вариантов (каждый банк, 言い換え, коллокации, регистр, реплики), уровень N3 и пометки регистра, соответствие `ru` ↔ `jp`, ошибки в `why`/`note`. Возвращает список: место → проблема → предложение.
- [ ] Правки по рецензии → снова validate + audit.
- [ ] Проверка в браузере (playwright): ход урока по шагам, по одной игре каждого типа на этом юните, карточки юнита.

## 9. Сдача
- [ ] `status: "ready"` в `units/NN.json`, `file` в `course.json`; юнит — в `frozen` в `tools/plan-config.json`, `node tools/plan.mjs`.
- [ ] Новые банки — в `banks/index.json`.
- [ ] Архив только изменённых файлов (`sora-n3-data-patch.zip`), обновить их в `app/` проекта; превью — по необходимости. Если менялся код (`js/`) — поднять `VERSION` в `sw.js`.
- [ ] Паспорт: отметить юнит, записать отзывы и решения.
