# Данные v2 и формат разметки

Всё учебное содержимое — статичные JSON в `data/`. Прогресс — отдельно, в IndexedDB браузера.
Перед коммитом данных: `node tools/validate.mjs` (0 ошибок обязательно).

## Разметка текста

Японский пишется как есть, в скобки берётся только то, что должно нажиматься.

| Запись | Что значит |
|---|---|
| `[傘]` | слово из словаря, id = написание |
| `[終わって=終わる]` | изменённая форма → лемма; чтение формы выводится само (おわって) |
| `[来なかった=来る]` | 来る тоже выводится (こなかった) |
| `[今日:きょう]` | явное чтение (исключения, слова вне словаря) |
| `[こと#2]` | номер значения в словаре (с 1) — подсветится в подсказке |
| `(が)` | частица, значения из общего списка `dict.particles` |
| `(で:чем наполнено)` | частица с пояснением именно для этого места |
| `{のに\|noni}` | грамматика, id из `grammar.json`. Если внутри есть слово с кандзи (`{寝ようとした\|youtosuru}`), оно находится по словарю само: фуригана над ним, в подсказке — блок «Слово внутри» с «＋ в карточки» (`innerWord` в markup.js) |
| `{ね}` | просто выделение без ссылки |

ASCII-пробелы вне скобок игнорируются — ими можно разделять токены для читаемости.
`\[` `\(` `\{` — буквальные символы. Японские скобки （） и 「」 — обычный текст.
Фуригана ставится только над кандзи и раскладывается по сегментам: 思(おも)い出(だ)した.

Пример: `[昨日]、[仕事](が)[終わって=終わる]{から|tekara}、[渋谷](へ)[行った=行く]。`

**Перевод текстов** — поле `tr` у текста (юнита и библиотеки): по строке на абзац, в чате — на реплику. На экране он скрыт, пока не нажата кнопка «Перевод» (выбор запоминается). Перевод — живой русский, не подстрочник. Смысл отдельных слов по-прежнему через нажатие.

## Файлы

```
data/
  course.json          карта курса: блоки → 25 юнитов (тема, задача, грамматика, кандзи, тексты, file)
  dict.json            общий словарь: words{} + particles{}
  grammar.json         конструкции: items{}
  kanji.json           кандзи: items{} + similar[[…]] (группы «не путать»)
  units/01.json …      наполнение юнита
  banks/index.json     список существующих банков
  banks/<gid>.json     банки предложений для грамматики
  library/index.json   библиотека чтения + library/<id>.json (paras, tr)
```

### dict.json → words
Ключ — id (обычно написание; омографы: `かける#1`).
```json
"傘": {"r": "かさ", "m": ["зонт"], "pos": "n", "reg": "colloq",
       "col": ["傘をさす"], "note": "…", "w": "傘"}
```
- `r` — чтение хираганой; `m` — значения по-русски (массив); `pos` — часть речи:
  `n v1 v5 vk vs n,vs adj-i adj-na adv conj pron propn col phrase exp`.
- `reg` — регистр, если не нейтральный: `colloq polite keigo formal written slang`.
- `col` — коллокации-примеры; самые важные — ещё и отдельными записями с `pos: "col"` (у них свои карточки).
- `pos: "phrase"` — живая реплика-реакция (えらい, わかる〜, 大変だったね). В уроке показывается отдельным блоком «Живые реплики».
- `note` — «по-русски думаем так → японец скажет так», ловушки. `w` — написание, если id отличается.
- Кандзи слова связываются с `kanji.json` автоматически.

### dict.json → particles
`"で": {"m": ["место действия", "средство", …]}`

### grammar.json → items
```json
"noni": {"pat": "〜のに", "m": "хотя; а ведь", "form": "простая форма + のに",
  "nuance": "…", "cmp": [{"g": "kedo", "pat": "〜けど", "note": "…"}],
  "unit": 10, "ex": ["разметка", …]}
```
`cmp` — группа «не путать»: `g` (ссылка, если описано) и/или `pat` (подпись).

### kanji.json → items
`"傘": {"m": "зонт", "on": ["サン"], "kun": ["かさ"]}` — кунъёми с точкой перед окуриганой.

### units/NN.json
```json
{"n": 1, "status": "draft|ready", "title": "…", "jp": "毎日のリズム", "task": "…", "intro": "1–2 предложения: о чём юнит",
 "words": ["id словаря", …], "phrases": ["id коллокаций/фраз/реплик"], "grammar": ["gid"], "kanji": "寝眠…",
 "notes": [{"ru": "Я устал.", "jp": "疲れた。", "note": "почему так"}],
 "texts": [{"id": "…", "title": "…", "titleR": "…", "ru": "…", "genre": "блог|чат|…", "paras": [["разметка", …], …], "tr": ["перевод абзаца", …]}],
 "output": {"tasks": […]}, "iikae": […], "calques": […], "collocations": […], "register": […], "replies": […], "chats": […]}
```
- Слова и фразы юнита должны встречаться в разметке предложений (тексты, банки, примеры) — иначе нет карточки-пропуска и задания в упражнениях; валидатор предупреждает.
- Чат: каждая реплика — отдельный абзац, начинается с `имя：` (полноширинное двоеточие). Первый говорящий — справа. В заданиях и карточках имя говорящего отрезается.
- `tr` — столько же строк, сколько абзацев в `paras` (валидатор проверяет).
- `grammar.json` → `detect`: подстроки, по которым выходное задание засчитывает конструкцию.
- Ход урока: слова → грамматика (разбор + «Выбери конструкцию») → кандзи → тексты → упражнения (10 заданий: по одному на конструкцию + слова, ошибки → `gaps`) → письмо (черновик в `kv unit:N`, образцы). Прогресс шагов — `kv unit:N.done`.

### banks/<gid>.json
```json
{"g": "kotonisuru", "items": [{"jp": "…{ことにした|kotonisuru}…", "ru": "смысл по-русски",
  "opts": ["ようになった", "つもりだった", "ようにしている"], "why": "почему ответ этот, а не остальные", "alt": []}]}
```
- Пропуск — токен `{…|gid}` этой грамматики. **Грамматика везде проверяется выбором** (урок, упражнения, карточки, игры), поэтому у каждого предложения нужны `opts` и `why`.
- `opts` — 3 неверных варианта **в той же форме** (время, вежливость), грамматичных в этом месте, но не передающих смысл `ru`. Брать из конструкций юнита и групп «не путать». Подходить по смыслу должен ровно один вариант.
- Если конструкция требует особой формы глагола (волитивная у (よ)うとする), глагол входит в пропуск: `{寝ようとした|youtosuru}`, варианты — `寝ることにした` и т. п.
- `ru` — живой перевод смысла, по нему и выбирают. 20–30 предложений на конструкцию.
- Те же предложения идут в игры «Собери фразу» и «На время». Для сборки предложение режется на кусочки автоматически (слово + частицы; определение склеивается с существительным; конструкция — отдельной плиткой, лишняя плитка — один из `opts`). Лучше всего работают предложения из 3–8 кусочков: короткие, без длинных перечислений.

### grammar.json → pairs
`"pairs": [{"a": "разметка", "ar": "смысл", "b": "разметка", "br": "смысл"}]` — пара предложений, где меняется только конструкция («Почувствуй разницу» в уроке).

### units/NN.json → output.tasks
```json
{"tasks": [{"title": "Подруге в LINE", "to": "подруга", "reg": "на ты, разговорно", "incoming": {"from": "ゆい", "jp": "…"},
  "situation": "конкретная ситуация", "plan": ["пункт 1 по-русски", …], "use": ["gid", …], "models": ["разметка образца"]}]}
```
2–3 ситуации с разным адресатом и регистром (друг / коллега / дневник). Пункты плана подводят к конструкциям юнита. Образцы — живой язык носителя в нужном регистре.
- `incoming: {"from": "ゆい", "jp": "разметка"}` — входящее сообщение на японском, на которое отвечаешь (показывается пузырём прямо над полем ответа). Пишется так, чтобы **не подсказывать** ответ: без конструкций юнита и ключевых слов из плана. Регистр сообщения задаёт регистр ответа.
- `heading: "разметка"` — для дневника вместо сообщения: японский заголовок записи.
- `situation` и `plan` — на русском (план нарочно не на японском: иначе задание превращается в списывание).

### units/NN.json → iikae (игра «Скажи иначе», 言い換え)
```json
{"g": "kotonisuru", "jp": "разметка с {…|gid}", "ru": "смысл",
 "ok": "разметка: та же мысль другими словами", "bad": ["разметка", "разметка"], "why": "почему ok, а не bad"}
```
- `ok` — пересказ без этой конструкции (ことにした ≈ と決めた, ようになった ≈ 前は〜なかったけど、今は〜).
- `bad` — 2 грамматичных фразы с другим смыслом, лучше всего — те же слова с соседней конструкцией («не путать»).
- Все варианты — с разметкой (на кнопках будет фуригана); слова — из словаря. 3–4 задания на конструкцию.

### units/NN.json → calques (игра «Найди кальку»)
```json
{"ru": "Я привык рано вставать.", "jp": "разметка естественной фразы", "bad": ["早起きを慣れた。", "早起きに慣れる。"], "note": "почему"}
```
- `bad` — 2 кальки с русского, **тоже разметкой**: после ответа все варианты показываются нажимаемыми (чтение и значение каждого слова). Слова калек добавляются в словарь с заметкой, почему здесь не годятся (同情, 真剣, 了解…), без `u`.
- Брать из `notes` юнита и типичных ошибок русскоговорящих. 10–15 на юнит.

### units/NN.json → collocations (игра «Коллокации»)
```json
{"head": "[目覚まし](を)", "ok": "かける", "bad": ["置く", "立てる", "作る"], "ru": "поставить будильник", "why": "почему так"}
```
- `head` — разметка: существительное + частица; `ok` — глагол **из словаря** (после ответа показывается `head[ok]`, слова нажимаются).
- `bad` — 3 неверных глагола: кальки с русского (принимать лекарство → 取る, писать экзамен → 書く), омофоны (立てる ↔ 建てる), глаголы, которые с этим словом значат другое (気がある, 気になる). Глаголы с кандзи — тоже в словарь, иначе на кнопке не будет фуриганы.
- 12–16 на юнит, сочетания из темы юнита и повседневные.

### units/NN.json → register (игра «Кому как сказать»)
```json
{"to": "Начальнику, на поручение", "ru": "Хорошо, понял.", "ok": "[承知しました=承知]。", "bad": ["[了解]！", "[わかった=わかる]。"], "why": "почему так"}
```
- Три варианта одного смысла в разных регистрах (простая форма / です・ます / кэйго); правильный выбирается по адресату `to`. Ситуация должна однозначно задавать регистр.
- Все варианты — разметкой. 8–10 на юнит.

### units/NN.json → replies (игра «Ответь репликой», 相づち)
```json
{"from": "ゆい", "jp": "[試験](に)[合格した=合格]！", "ok": "[おめでとう]！", "bad": ["[大変だったね]。", "[無理しないでね]。"], "why": "почему именно эта реакция"}
```
- Сообщение друга и три короткие реакции разметкой; верная — одна, неверные — реакции из того же набора, но к другой ситуации (いいなあ на беду, えらい на невезение). Ситуация должна однозначно задавать реакцию.
- Реакции берутся из фраз юнита (`phrases`) — так игра закрепляет именно их. 10–14 на юнит.

### units/NN.json → chats (игра «Ответь в чате», 返信)
```json
{"to": "ゆい · подруга", "reg": "на ты", "ru": "что нужно сказать (по-русски)", "use": ["tsumori"],
 "incoming": {"from": "ゆい", "jp": "[週末](は)[何](を)[する](の:…)？"}, "model": "[週末](は)[ゆっくり][寝る]{つもり|tsumori}。"}
```
- Вместо `incoming` можно `heading` (заголовок дневника) — запись без собеседника.
- `use` — конструкции юнита; в образце `model` каждая обязана стоять разметкой `{…|gid}` (валидатор проверяет). Во время ответа чипы подсвечиваются по `grammar.detect`.
- `ru` — смысл, а не перевод образца: пусть остаётся свобода сказать по-своему. 8–10 на юнит.

### Игра «Скажи быстро» — без отдельных данных
Берёт слова и фразы юнита (`words`, `phrases`: значение из словаря, после ответа — чтение и `note`) и `notes` (русская фраза → японская). Пометка регистра (`reg`) показывается в задании.

### Игры «Чтения» и «Слово в контексте» — без отдельных данных
Берут слова юнита с кандзи (кроме коллокаций и реплик).
- «Чтения»: неверные чтения строятся сами — слово выравнивается по `kanji.json` (он/кун, озвончение, っ) и одно чтение кандзи заменяется другим (予定 → よさだ, よじょう); не хватило — слова с теми же кандзи, правки долготы и っ. Поэтому у кандзи юнита в `kanji.json` должны быть все частые он/кун.
- «Слово в контексте»: японская фраза из корпуса (тексты, примеры, банки) с пропуском, варианты — слова кандзи без фуриганы, без русского. Пропуск делается, только если слово встанет грамматически: существительное целиком или основой перед する (寝坊|しちゃった), глагол и い-прил. — в словарной форме. Неверные варианты — того же класса, не из этих юнитов (слова одной темы часто подходят оба), без взаимозаменяемых слов времени и однокоренных; строка не берётся, если слово видно в ней ещё раз. Если вариант всё же подошёл — «засчитать» после ответа. Чем больше в юните фраз со словом в простой форме, тем больше заданий.

## Стиль языка
Только живой, частотный японский, которым носители реально пользуются в речи и переписке. Редкие книжные слова — только если без них никак, с пометкой регистра. Разговорные формы (〜ちゃう, 〜てる, んだよね) — в чатах и репликах; в вежливых ситуациях — です／ます.

## Прогресс (IndexedDB «sora»)
- `items` — что в изучении: `{id:"w:傘"|"g:noni"|"k:傘", kind, ref, decks[], added, custom?, auto?}`.
  Колоды: `text:<id>`, `unit:<n>`, `manual`, `kanji`. `custom` — своё слово вне словаря `{w,r,m[]}`.
- `cards` — `{id:"<item>|<type>", item, type, state:new|learning|review|relearning, s, d, due, last, ivl, reps, lapses, firstAt, leech}`.
- `reviews` — журнал `{card, at, grade, state, ivl}`; `kv` — настройки (`newPerDay`), прохождение юнитов `unit:N`.
- `gaps` — пробелы: `{at, kind:"miss"|"leech", src, jp, ru, said, note, g?, line?, key?, item?, fixedAt?}`.
  `src` — `unit:N` или `game:<игра>`; `g` — конструкция, `line` — разметка предложения банка, `key` — задание игры (`ii:1:3`, `cq:1:0`, `co:1:5`, `rg:1:2`, `yo:遅刻`, `cx:遅刻`, `sb:遅刻`), `item` — слово (`w:遅刻`).
  Верный ответ в игре ставит `fixedAt` — запись считается закрытой (режим «Мои пробелы» её больше не берёт).
- Игры: `kv gameScope` — `{mode:"unit"|"block"|"all"|"gaps", unit:N, block:"I"}` (юнит и блок помнятся отдельно от режима); `kv games` — `{asm:{plays, last}, blitz:{plays, best, last}, …}`.
- Сохранение — кнопка «Сохранение» вверху справа: скачать / загрузить один JSON со всеми хранилищами. Дата последнего сохранения — `localStorage sora:lastSave`.
- В `localStorage` (не в файле прогресса): тема `sora:theme` (`auto|light|dark|aoshingo|kohaku|rock|showa|yokocho` — см. «Темы» в README), фуригана и перевод `sora:prefs` `{f, t}`, последний экран `sora:last`.

## Карточки
- Типы: слово — `ru-jp` (главная), `jp-ru`, `cloze` (если слово есть в каком-нибудь тексте/примере/банке), `col` (если у слова есть коллокация из словаря);
  грамматика — `gap` (предложение каждый раз случайное из примеров, текстов и банка); кандзи — `k-mean`, `k-read`, `k-sim` (если кандзи в группе `similar`).
- Кандзи-элемент создаётся сам, когда в изучении 2+ слова с этим кандзи и кандзи есть в `kanji.json`.
- Карточки создаются из элементов при каждом открытии (`sync()`): новый текст в данных → у слов появляются новые пропуски.
- FSRS-4.5, целевая память 90 %, сутки с 4:00. «Снова» → через 10 минут в той же сессии.
- Первый шаг для ещё не выученной карточки: Трудно 1 д, Хорошо 2 д, Легко 4 д; дальше — FSRS (≈ 2 → 4 → 15 д → 2 мес).
- Лимит новых в день (`kv.newPerDay`) не касается главной карточки (`ru-jp`) элементов из колод `unit:*` — они выходят сразу.
- «Убрать» = `items.suspended: true` (+ `pausedAt`): карточки не попадают в очередь, история сохраняется; «Вернуть» снимает флаг.
- Одна карточка элемента в день: плановое повторение важнее новой сестринской; новые сестринские вводятся после первой карточки.
- Пиявка: 4+ провала → запись в «Мои пробелы».
- Фильтр видов для общей очереди — `kv kinds` (`["word","grammar","kanji"]`, минимум один). Способ ответа — `kv answerMode`: `self` (по умолчанию: карточки с вводом показываются как «сказать и перевернуть») или `type`. Выбор из вариантов не меняется.
